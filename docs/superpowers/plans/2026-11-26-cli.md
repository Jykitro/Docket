# CLI Plandillo: план разработки

Цель: агент (Claude Code, Codex, любой с shell) работает с доской полностью через команду `plandillo-cli …`, без настройки MCP. CLI ставится привычным для каждой ОС способом: Homebrew на macOS и Linux, Scoop и winget на Windows, deb/rpm на Linux, а также одной командой `curl | sh` или `irm | iex`.

## Что уже есть

- `.goreleaser.yaml` собирает `plandillo` под linux, darwin и windows (amd64, arm64) и выкладывает их в GitHub Release по тегу `v*` (`.github/workflows/release.yml`). Пакетных менеджеров нет.
- `cmd/plandillo/main.go` без аргументов запускает сервер. Подкоманды `code-runner` и `code-eval` служебные.
- Агентский канал `/mcp` (и `/mcp/code`) принимает workspace-токен (`Authorization: Bearer`) или OAuth с динамической регистрацией (`/oauth/register`, PKCE). Через него работают режим «только чтение», переключатели инструментов, журнал вызовов и автор «агент».
- REST `/api/...` действует от имени человека по cookie-сессии, поэтому агентскому CLI он не подходит.
- В `go.mod` уже есть `github.com/modelcontextprotocol/go-sdk` с клиентом.
- Установка skills (`skills.InstallScript`) — bash-скрипт, работает только на macOS и Linux. Хуки в `plandillo-setup` используют `grep` и `echo '…'`, на Windows они не работают.

## Главное решение: CLI как MCP-клиент

CLI — тонкий клиент к существующему `/mcp`. Список команд берётся из `tools/list` во время работы, а не из отдельного кода.

- Новый инструмент в `MCPTools` сразу появляется в CLI, его не нужно дописывать в двух местах.
- Валидация, история, live-обновления, режим доступа и журнал вызовов те же, что у MCP: слой `service` не трогаем, правило слоёв из AGENTS.md соблюдено.
- Для ядра CLI сервер менять не нужно (проверить в фазе 1: Host/Origin guard для запроса без Origin и OAuth в локальном режиме).

## Решения, которые нужно принять до старта

2. **Репозитории для пакетов:** `huntly-digital/homebrew-tap` и `huntly-digital/scoop-bucket`, а также PAT-секрет с правом push в них (и в форк `winget-pkgs`).

## Команды

| Команда | Что делает |
|---|---|
| `plandillo-cli login [URL]` | OAuth через loopback `127.0.0.1:<порт>` с PKCE и динамической регистрацией, как `gh auth login`. `--with-token` читает workspace-токен из stdin, `--code` дополнительно авторизует Code Mode (OAuth-токен привязан к `/mcp` или `/mcp/code`). По умолчанию URL `http://localhost:7777` |
| `plandillo-cli logout`, `plandillo-cli status` | Удалить сохранённый доступ; показать URL, рабочее пространство, режим доступа и число инструментов |
| `plandillo-cli tools [--json]` | Инструменты из `tools/list`: имя, read/write, описание; с `--json` ещё и схема |
| `plandillo-cli <tool> [args]` | Вызов любого инструмента: `plandillo-cli get_today`, `plandillo-cli get_task --id PLD-12`, `plandillo-cli create_tasks '{"tasks":[…]}'`, `… @file.json`, `… -` (stdin) |
| `plandillo-cli code '<js>'` или `-` | Code Mode через `/mcp/code`: `return await codemode.get_today({})` |
| `plandillo-cli skills install [--agent claude-code\|codex] [--global]` | Записывает три skill из встроенного `skills/` на любой ОС, в том числе Windows |
| `plandillo-cli hook session-start\|stop` | Кроссплатформенная замена `echo` и `grep` в хуках Claude Code и Codex |

Контракт для агентов:

- stdout содержит ровно результат инструмента в компактном JSON, как в MCP; `--pretty` форматирует его для людей.
- Ошибка пишется в stderr в виде `code: message`, как в MCP.
- Коды выхода: 0 — успех, 1 — ошибка инструмента, 2 — неверные аргументы, 3 — нужна авторизация (401, 403), 4 — сервер недоступен.
- Флаги строятся из верхнеуровневых скалярных полей схемы (`--id`, `--q`, `--limit`). Вложенное передаётся JSON-аргументом.
- `--agent` или `PLANDILLO_AGENT` уходит в `clientInfo.name`, чтобы в истории было видно, какой агент сделал изменение.
- `PLANDILLO_URL` и `PLANDILLO_TOKEN` перекрывают конфиг (для CI и контейнеров).
- Доступ хранится в `os.UserConfigDir()/plandillo/cli.json` (или `PLANDILLO_CLI_CONFIG`) с правами 0600; refresh-токен обновляется сам. Токены не логируются.

Не входит в v1: человеческие алиасы (`plandillo-cli today`, `plandillo-cli board`), несколько профилей досок, системный keychain, самообновление (`plandillo-cli update`): обновлением занимаются пакетные менеджеры.

### Фаза 3. Установка на всех ОС (`.goreleaser.yaml`, `release.yml`)

- [x] **Сборка:** в `.goreleaser.yaml` отдельный build `plandillo-cli` (`main: ./cmd/plandillo-cli`, те же ОС и архитектуры) и свой архив `plandillo-cli_{{ .Version }}_{{ .Os }}_{{ .Arch }}`; в пакеты попадает только он. Версия вшивается через `-X plandillo/internal/cli.Version`.
- [x] **macOS и Linux:** Homebrew через `homebrew_casks` (в GoReleaser v2 он заменил `brews`), публикация в `huntly-digital/homebrew-tap`. Без нотаризации — хук снятия `com.apple.quarantine`. Команда: `brew install huntly-digital/tap/plandillo-cli`. Cask содержит и Linux; без `HOMEBREW_TAP_GITHUB_TOKEN` он только пишется в `dist/`.
- [ ] **Windows:** `scoops` в `huntly-digital/scoop-bucket` (`scoop bucket add plandillo https://github.com/huntly-digital/scoop-bucket` и `scoop install plandillo-cli`), затем `winget` (PR в `microsoft/winget-pkgs`; первую публикацию модераторы проверяют вручную) → `winget install Plandillo.CLI`.
- [ ] **Linux-пакеты:** `nfpms` с deb, rpm и apk пакета `plandillo-cli` в релизе. AUR (`aurs`) — по запросу.
- [x] **Одна команда:** `install.sh` и `install.ps1` отдаёт сама доска (`/api/cli/install.{sh,ps1}`, `internal/cli/installer`): ОС и архитектура, `checksums.txt`, установка в `~/.local/bin` или `%LOCALAPPDATA%\Programs\plandillo-cli` (с PATH), затем `plandillo-cli login` на эту доску. Архивы CLI без версии в имени, чтобы работал `releases/latest/download`. Копия на лендинге — по желанию.
- [ ] `go install …/cmd/plandillo-cli@latest` — описать как вариант для Go-разработчиков. Сейчас не работает: модуль называется `plandillo`, а не `github.com/huntly-digital/plandillo`.
- [ ] CI: `goreleaser check` и `release --snapshot` в `ci.yml`; `go test ./internal/cli/...` на `windows-latest` и `macos-latest`. `goreleaser check` добавлен; snapshot и тесты на Windows/macOS ещё нет.

Версии до 1.0: теги `v0.x.y` — обычные релизы (brew обновляет их через `brew upgrade`), суффикс `-rc.N` даёт pre-release на GitHub.

## Готово, когда

На чистых macOS, Windows и Linux CLI ставится одной командой пакетного менеджера, `plandillo-cli login` проходит в браузере, а Claude Code и Codex без MCP-сервера проходят цикл из skill: `get_today` → `create_tasks` → `add_note` → `move_tasks`. В истории задачи видно имя агента, `make check` зелёный, тесты `internal/cli` проходят на трёх ОС в CI.
