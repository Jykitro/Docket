# Вики проекта (третья вкладка) — спека

Дата: 2026-11-07. Статус: ждёт проверки.

## Цель

У каждого проекта есть вкладка «Вики» рядом с «Доска» и «Список»: хранилище markdown-страниц с редактором и связями. Пример использования: после анализа кода ассистент записывает страницу «Страница настроек: готово на 70%, данные моковые», человек читает и правит её в UI. Страницы связаны между собой и с задачами.

## Решения

- Страницы лежат в SQLite (таблица `pages`), а не в файлах: сохраняется модель «один процесс, одна БД на пользователя».
- Связи не хранятся отдельной таблицей, а вычисляются при чтении из `body_md`. Для десятков страниц на проект этого достаточно. Если страниц станут тысячи, добавляется таблица `page_links`, API не меняется.
- Адрес страницы идёт по числовому `id` (`/p/{slug}/wiki/{id}`), без slug: названия на русском, транслитерация не нужна.
- Всё идёт через `service` (правило слоёв), действия пишутся в `activity` с автором `denis` или `claude`.

## Данные

Миграция `003_pages.sql`:

```sql
CREATE TABLE pages (
  id         INTEGER PRIMARY KEY,
  project_id INTEGER NOT NULL REFERENCES projects(id),
  parent_id  INTEGER REFERENCES pages(id),
  title      TEXT NOT NULL,
  body_md    TEXT NOT NULL DEFAULT '',
  position   REAL NOT NULL,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
CREATE UNIQUE INDEX idx_pages_title ON pages(project_id, lower(title));
```

Ограничения (проверяет `service`, сообщения говорят, что не так и что можно): название 1–120 символов, тело до 200 КБ, родитель из того же проекта, цикл в дереве запрещён.

## Связи

Разбор `body_md` на Go (`[[...]]` и коды задач), всё остальное вычисляется из него.

- `[[Название]]` — ссылка на страницу проекта, поиск по названию без учёта регистра. Нет такой страницы — ссылка «не найдена».
- Код задачи вида `TRK-07` (`[A-Z][A-Z0-9]{1,4}-\d+`) — ссылка на задачу, если она существует.
- Обратные ссылки страницы: `LIKE '%[[Название]]%'` по страницам проекта. Коды задач: `LIKE` по коду с проверкой регэкспом по границам слова, чтобы `TRK-07` не находил `TRK-070`.
- Известное ограничение (shortcut): ссылки внутри блоков кода тоже считаются при разборе на сервере. Исправляется разбором с пропуском fenced-кода, когда это начнёт мешать.
- Переименование: заголовок меняется, а `[[Старое]]` заменяется на `[[Новое]]` в остальных страницах проекта в одной транзакции.
- Удаление страницы: дочерние переходят к её родителю, `[[...]]` в других страницах становятся «не найдена».

## API

REST (проверка доступа как у задач):

| Метод и путь | Что делает |
|---|---|
| `GET /api/projects/{slug}/pages` | Плоский список `id, parent_id, title, position, updated_at`, без тел |
| `POST /api/projects/{slug}/pages` | Создать: `title`, `body_md`, `parent_id` |
| `GET /api/pages/{id}` | Страница + `backlinks` (id, title), `links.pages`, `links.tasks` (разрешённые ссылки) |
| `PUT /api/pages/{id}` | Правка `title`, `body_md`, `parent_id`; `updated_at` для проверки конфликта |
| `DELETE /api/pages/{id}` | Удалить |
| `GET /api/tasks/{code}/pages` | Страницы, где упомянута задача |

Ошибки: `invalid_argument`, `not_found` и новый `conflict` (409): `PUT` с устаревшим `updated_at`. Правка публикует событие в `events`, UI обновляется по SSE, как для задач.

## MCP

Четыре инструмента в `service.MCPTools`, результаты компактные (без тел в списках):

| Инструмент | Тип | Поведение |
|---|---|---|
| `list_pages(project)` | read | `[{id, title, parent, updated_at}]` |
| `read_page(project, title)` | read | `{id, title, parent, body_md, updated_at, backlinks[], tasks[]}` |
| `write_page(project, title, body_md, parent?, expected_updated_at?)` | write | Создаёт или полностью заменяет страницу по названию; с `expected_updated_at` возвращает `conflict` при устаревшем |
| `append_to_page(project, title, text)` | write | Дописывает в конец через пустую строку; страница должна существовать |

Удаления через MCP нет намеренно: ассистент не должен стирать вики. Write-инструменты блокируются в read-only режиме через `IsWriteTool`.

## Интерфейс

- Третья вкладка «Вики» в `Board.tsx` (рядом с «Доска» и «Список»), маршрут `/p/{slug}/wiki/{id?}` в `App.tsx`. Компонент `web/src/Wiki.tsx`.
- Слева дерево страниц и кнопка «Новая страница». Справа страница.
- Чтение: markdown через существующий `renderMarkdown`, расширенный инлайн-правилом для `[[...]]` и кодов задач (блоки кода не затрагиваются). Внутренние ссылки открываются в приложении, не в новой вкладке. Ненайденная ссылка показывается пунктиром и по клику предлагает создать страницу.
- Правка: textarea и переключатель «Редактор / Превью», сохранение кнопкой и по ⌘S, предупреждение о несохранённых изменениях. Получив `conflict`, редактор показывает баннер «страница изменилась» с выбором: загрузить новую версию или сохранить поверх.
- Под текстом блоки «Ссылаются сюда» и «Задачи». В `TaskPanel` блок «Упомянута на страницах».
- Тексты на русском, английском и украинском (`tr` и `messages.ts`), даты через `locale()`, без внешних ресурсов.
